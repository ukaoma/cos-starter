Swap the intelligence. Keep the operating system.

What is an AI harness?

An AI harness is the operating system around a model: the instructions, context, memory, tools, permissions, workflow logic, and persistence that let it do useful work again and again.

Ask a bare model a question and it produces an answer. Put that model inside a harness and it can inspect the right files, retrieve what happened last week, choose an approved tool, finish a multi-step task, record the result, and leave enough state for the next session to continue.

Anthropic describes a harness as the instructions and guardrails a model operates under. OpenAI's account of the Codex harness adds the agent loop, thread lifecycle, tool execution, extensions, configuration, authentication, and persistence. The boundary varies by product. The idea does not: the model is only one component of the working system.

AI model vs. AI agent vs. AI harness

LayerWhat it doesWhat survives a model swap
ModelReasons, generates, interprets, and decides what to do next.Usually nothing. It is the replaceable engine.
AgentThe working system you experience: a model acting with tools inside an environment.Only what its harness preserves.
HarnessProvides context, memory, tools, permissions, orchestration, and continuity.Your operating rules, corpus, workflows, and outputs.
MCPStandardizes connections to tools, resources, and prompts.Portable connections, when the next host supports them.

Swap the model and the top row leaves. The harness row is what you keep. MCP matters, but it is closer to a universal port than a harness: the harness still decides which connections exist, what context is retrieved, what needs approval, what gets recorded, and how work continues after the context window ends.

Context engineering vs prompt engineering

The eight layers you own live in one folder.

A better model raises the ceiling. A better harness raises the floor. These layers keep working when you swap the model underneath them, and each one is a file you can open.

  1. Rules you set. Who you are and how the AI should work, before it starts.

    Lives in AGENTS.md, imported by CLAUDE.md

    Start here. Write the operating map: who you are, what you own, your people, your priorities. Keep it short and link to deeper sources.

  2. Context that stays. People, decisions, and history, kept outside the chat window.

    Lives in context/people.md, corrections.md, intelligence/

    Choose a durable shape. Readable files for people and decisions, lists for tasks, search for retrieval. Version what matters.

  3. Hands on the world. Files, search, calendar, email, and CRM, wired in through MCP.

    Lives in .mcp.json, mirrored for Codex

    Connect one real source. Calendar, email, meetings, or tasks. One live connection beats ten empty ones.

  4. Permission to act. What it may send or change, and where you sign off first.

    Lives in the Rules in AGENTS.md, fed by corrections.md

    Make every correction compound. Fix the source, the rule, or the retrieval path, not just the answer. When a correction repeats, /learn promotes it to a rule.

  5. How work moves. Planning, retries, and handoffs that hold a long task together.

    Lives in .claude/commands/, mirrored for Codex

    Turn recurring work into skills. Daily brief, meeting prep, reflection: named workflows with inputs, checks, and an expected output.

  6. What remains. The files and logs that let tomorrow start where today stopped.

    Lives in tasks.md and this week's wk<NN>_<year>/ folder

  7. Ears and a voice. Dictation in and speech out, running on hardware you control.

    Lives on your Mac in COS Control, outside the folder

  8. Runs without you. Work on a clock, or in parallel, while you are away.

    The morning brief runs on a schedule you set in COS Control

Start with a folder, not a platform migration.

There was a model last cycle that felt magical. It was the first one that made me tell it: explain this to me simpler, I feel dumb. Then it got pulled from all of us. That is the whole lesson. If a frontier provider can throttle your access to the intelligence at any point, you were never building a moat. You were renting theirs.

The price tag says the same thing. Frontier plans are priced to get you hooked, and the subsidy does not last. Teams find that out when the meter starts counting for real.

Meanwhile the models are converging: the same intelligence, the same tool use, a new leader every cycle and the gap closing right behind it. When every engine can do the job, the engine stops being the decision. What decides is what the engine knows about you, and how fast you can move that knowledge to the next one. I can swap the top models under COS and get the same operator back, with the same priorities and the mistakes it already learned not to repeat.

The frontier will keep the tip of the spear. Open models keep closing in, and compute is moving to the edge. Own the harness and you get to move with all of it.

Treat AI memory as a database you own.

A chat history is a receipt. A memory is a record: people, decisions, tasks, meetings, and corrections, stored as files and indexes on hardware you control.

Owned
Ordinary files you can read, back up, and move, not a memory feature locked inside one vendor's app.
Structured
Identity and decisions in readable files, tasks in lists, retrieval through search.
Compounding
Every correction lands in the record, so the next model inherits it on day one.
Queryable
Exposed over MCP, the same record answers Claude, Codex, Cursor, ChatGPT, and whatever ships next.

The harness still runs the door: what is retrievable, what needs approval, what gets written back. Portability without policy is a leak. Portability with policy is a moat.

Local storage is not the same as local inference.

Your corpus can stay on your machine while selected context goes to a hosted model for a task. Provider terms still apply to anything sent. A serious harness makes that boundary visible instead of hiding it.

A harness under real operating load.

COS began as an AI chief of staff built while running marketing and digital transformation across a multi-brand software portfolio, alongside two operating businesses and a family. The job was never to chat better. It was to keep context across the places real work happens. It runs on Claude Code, Codex, and Cursor today.

Before the meeting, retrieve the people, history, and unfinished work.

The model does not need every document. The harness finds the small set that changes the answer, and Today opens with it.

During the work, use tools inside explicit boundaries.

Search meetings, read tasks, inspect files, draft, run an analysis. Anything that becomes visible outside waits for your approval first.

After the decision, write the durable artifact.

The decision, the correction, the output, and the next step go back to the record instead of disappearing into a transcript.

Next model, next surface, same relationship.

The same memory shows up in a terminal, a desktop app, a phone, or a pair of smart glasses. Some days you read it. Some days you just talk.

What is an AI harness?

An AI harness is the operating system around a model. It holds your memory, your tools, the rules it follows, and the permissions and state that let it keep working. That structure is what turns a single answer into a system that does useful work again and again.

Is an AI harness the same as an AI agent?

No. The agent is the working system produced by a model operating inside a harness with tools and an environment. The harness is the structure that coordinates those parts and determines what survives between runs.

Is MCP an AI harness?

No. Model Context Protocol standardizes how AI applications connect to tools, resources, and prompts. MCP can be an important connection layer inside a harness, but it does not define the complete memory, policy, workflow, or persistence system.

Can one harness use Claude, GPT, and Gemini?

A harness can support multiple models. COS runs on Claude Code, Codex, and Cursor today; GPT, Gemini, and local models require additional adapters. Running the harness and querying its memory are separate questions, and the second one is already open to every model.

What is an AI memory layer?

The AI memory layer is the record of who you are, who you work with, what you decided, and what you corrected, kept separate from any single model or app. A model reads from it before it answers and writes back to it after. When the layer lives outside the assistant, as files and indexes you own, it becomes shared memory that any model can use.

Can ChatGPT, Claude, Cursor, and the next assistant all query the same memory?

Yes, when the memory lives as a resource instead of inside one app's chat history. COS exposes your memory over MCP, so any MCP-capable host reads the same record: Claude, Cursor, Codex, ChatGPT, or whatever ships next. One connector, one memory, no re-explaining. The harness still decides what is exposed, what is retrieved for a given question, and what needs your approval.

Is Claude memory or ChatGPT memory portable?

Not on their own. Built-in memory features live inside that vendor's app and follow that vendor's rules. You cannot hand them to a different model. A harness inverts this: the memory sits outside every assistant, and each model connects to it. Switching engines keeps the record intact.

What is a memory MCP server?

A memory MCP server exposes stored memory as resources and tools over the Model Context Protocol, so any MCP client can read from it and write to it. It is the plumbing that makes one shared AI memory reachable from several assistants. It is not the whole harness: retrieval, policy, approvals, and persistence still need an owner.

Does a local AI harness keep all data private?

Not automatically. A local-first harness can keep the durable corpus and outputs on devices you control. Any context sent to a hosted model for inference is still processed under that provider's terms and data controls. Local storage and local inference are separate choices.

Why does a harness matter for personal AI memory?

The harness decides what gets remembered, how it is organized, when it is retrieved, and how corrections compound. That turns scattered chats into durable working memory that can survive a new model, interface, or device.
